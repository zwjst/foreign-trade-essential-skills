# 医疗器械海外客户开发 Skill

## 一、目标与适用范围

本 Skill 用于医疗器械出口销售的潜在客户开发，适用于医生、外科医生、放射科医生、医院、诊所、影像中心、医疗集团及当地经销商。默认业务背景为 Perlove Medical 医疗影像设备出口销售。

初始产品范围：
- Mobile DR / 数字化移动 X 射线摄影系统
- Fixed DR / 固定式数字化摄影系统
- Suspended DR / 悬吊式 DR
- Dynamic DR / DRF / 数字化摄影与透视系统
- Mobile C-arm / 高频移动 C 臂、介入型移动 C 臂
- 3D C-arm
- CBCT

产品目录仅用于初步匹配，不证明某型号当前可供货、已在目标国注册或适用于某项术式。型号、参数、认证、注册、安装条件、价格和交付承诺，必须依据当前有效的制造商文件、法规资料及工程确认。

## 二、强制执行顺序

每位医生线索必须按照以下报告顺序输出，不得将联系方式或话术提前到身份核实之前，也不得把话术放到机构、论文或产品分析之后：

1. **医生身份及专业核实**
2. **个人 WhatsApp、电话、邮箱全面检索**
3. **西语 WhatsApp 和邮件开发话术（附中文）**
4. **当前执业机构及合作医院调查**
5. **学术论文、临床术式及设备需求分析**
6. **医院设备配置、历史采购及采购负责人调查**
7. **Perlove 产品匹配及客户评分**
8. **下一步开发计划**
9. **客户登记摘要**

第 1–7 部分为核心调查报告；第 8–9 部分保留为执行和 CRM 收尾。若用户提供了既有沟通记录，第 3 部分必须根据真实进度输出追加或跟进内容，不得重复已发送的首次开发话术。

## 三、核心执行原则

1. **原始线索是搜索起点。** 用户提供的姓名、国家、城市、专业、机构、电话、邮箱和目录链接直接作为检索线索。不要先逐字段复述或审计原始表格；立即开展身份、专业和公开联系方式调查。原始字段未经独立证据支持，不得升级为已核实事实。
2. **先核实身份及专业，再全面检索联系方式。** 先确认是否为目标医生、专业/亚专科是否准确、是否存在同名人员或资料冲突。身份暂未完全确认时仍可继续查找联系方式，但必须标记归属不确定，不能将不同人员的信息合并。
3. **联系方式检索必须全面。** 优先寻找医生本人公开的专业 WhatsApp、个人手机、专业邮箱；同时检查诊所预约渠道、医院科室、秘书处和机构通用渠道。每条联系方式必须记录来源、归属和验证状态。
4. **话术必须紧跟联系方式。** 报告第 3 部分固定为西语 WhatsApp 和邮件话术，均附完整中文翻译。联系渠道不属于医生本人时，话术必须面向真实接收者，不得假装联系到医生本人。
5. **证据优先于推断。** 明确区分官方来源证实、医生本人自述、论文记录、机构公布、合理推断和待确认事项。
6. **不得编造。** 不猜测电话、WhatsApp、邮箱、医院任职、论文、设备型号、采购记录、认证或评分依据。猜测邮箱格式不得作为可用联系方式输出。
7. **个人与机构联系方式严格区分。** 诊所预约号码不自动等于医生个人号码；医院总机不等于科室电话；手机号码不等于 WhatsApp 已开通；自动回复不等于医生本人确认。
8. **现任与历史经历严格区分。** 旧论文、历史目录、过期保险目录和早年任职信息不得直接描述为当前状态。
9. **临床需求不能由专业名称直接推定。** 专业方向只能生成待验证问题，不能证明医生实际开展某项手术、使用 C 臂、拥有设备或参与采购。
10. **医生、机构、采购角色分别研究。** 临床使用者、科室主任、医学工程、影像科、采购、财务及法定代表人可能是不同人员。
11. **先审阅沟通历史，再写话术。** 区分实际发送、实际回复、自动回复、秘书回复、医生本人回复、第三方转介和未发送草稿。用户说“已经发了”或“只追加”时，仅输出新增内容。
12. **不擅自联系客户。** 只准备报告和话术；未经用户明确授权且没有相应工具，不发送 WhatsApp、邮件、表单或采购请求。
13. **遵守隐私和反骚扰要求。** 仅使用公开发布的专业联系信息；不搜集患者资料、私人家庭信息、住址或与职业无关的个人信息。收到拒绝或退订要求后停止相应范围的联系。

## 四、输入与启动方式

接受单条或批量线索。输入可能是表格行、CSV、CRM 导出、协会目录、会议名录、论文作者信息、截图、WhatsApp 记录或用户备注。

可能包含：
- 姓名及姓名顺序、国家、城市、专业、亚专科
- 医院、诊所、科室、大学、经销商
- 电话、WhatsApp、邮箱、网站、社交媒体
- 原始目录链接、论文、会议、招标或采购记录
- 之前发送的 WhatsApp、邮件和客户回复

处理规则：
- 保留用户提供的姓名原始顺序、拼写和重音符号；如发现不同写法，分别记录，不擅自合并。
- 将原始线索作为检索入口，不要把原始表格的每个字段逐一重复作为报告开头。
- 发现同名人员时，按专业、城市、机构、论文、教育背景和职业经历交叉判断；仅凭姓名不得合并。
- 输入中已有沟通记录时，先识别已发送、已收到、自动回复、转介和未发送草稿，再决定首次联系还是后续跟进。
- 批量开发时每位客户独立建档，避免联系方式、论文、机构和评分串线。

## 五、医生身份及专业核实

本部分必须作为报告第 1 部分。

### 5.1 身份核验维度

交叉比对：
- 完整姓名、姓名原始顺序、拼写及重音符号
- 国家、城市及可能的执业地区
- 专业、亚专科、专科资质及执业范围
- 当前和历史执业机构
- 教育经历、专科培训及职业履历
- ORCID、论文作者身份、通讯作者信息
- 官方医生目录、专业协会和政府执业登记
- 公开职业主页、学术活动及会议讲者资料

### 5.2 专业验证

优先使用政府执业登记、医院/大学官方医生档案、专科协会、论文作者档案和专业会议资料。明确区分：
- 已正式确认的专科资质
- 官方机构或医生本人公开描述的专业
- 论文或研究体现的研究方向
- 根据关键词推断的可能方向
- 尚未确认或存在冲突的专业信息

不能仅凭论文主题、单一目录分类或关键词规则推断专科资质。若资料只显示“Cirugía”或“Medicina”，不得擅自细化为某一亚专科。

### 5.3 身份置信度

- **已确认：** 权威当前来源加独立佐证，或至少两个独立可靠来源一致。
- **高度可信：** 多个属性吻合，但现任机构或直接身份仍有一项未完全确认。
- **暂定：** 只有一个来源或匹配属性有限。
- **冲突：** 可靠来源对姓名、专业、地点或机构有矛盾。
- **未解决：** 无法区分同名人员。

必须说明专业核实结论、主要证据、证据年份和仍需确认的字段。

## 六、个人 WhatsApp、电话、邮箱全面检索

本部分必须作为报告第 2 部分，紧接身份及专业核实。

### 6.1 检索覆盖

优先检索医生本人公开的专业联系渠道，按以下来源逐层展开：
1. 医生本人专业网站、个人诊所网站、个人预约页面和职业主页。
2. 医院/诊所官方医生目录、个人介绍和科室页面。
3. 官方预约平台、保险公司医生目录和医疗服务目录。
4. 论文作者页、通讯作者邮箱、ORCID、大学研究档案。
5. 医学协会、专科协会、学术会议讲者页面。
6. 官方 LinkedIn、专业社交主页和公开职业访谈。
7. 医疗机构官方电话、科室电话、秘书处、预约中心和官方 WhatsApp。
8. 可信第三方医生目录和商业目录，仅作为发现入口并尽可能交叉核验。

### 6.2 搜索词组合

根据目标国家使用当地语言及英语，组合：
- 完整姓名 + 城市 / 国家
- 完整姓名 + 专业 / 亚专科
- 完整姓名 + 医院 / 诊所 / 大学
- 完整姓名 + WhatsApp / celular / móvil / teléfono / contacto / citas / correo / email
- 完整姓名 + ORCID / PubMed / Google Scholar / ResearchGate / LinkedIn
- 完整姓名 + conferencia / congreso / ponente / autor / publicación
- 完整姓名 + número / móvil / teléfono directo / agenda / consultorio
- 机构名称 + teléfono / WhatsApp / contacto / correo / directorio médico

西语地区特别注意双姓、姓名顺序、重音符号、缩写和常见拼写差异。新发现的机构、域名、协会或论文如提供合理的新检索路径，应继续追踪。

### 6.3 每条联系方式必填字段

- 原始显示形式及标准化形式
- 渠道类型：个人手机、WhatsApp、邮箱、诊所预约、医院总机、科室、秘书处、社交账号等
- 归属对象：医生本人、诊所、医院、科室、助理、第三方或未知
- 来源 URL 和来源类型
- 来源页面发布日期或可见更新时间
- 是否有第二个独立来源支持
- WhatsApp 是否由来源明确标注为 WhatsApp
- 是否经过实际消息测试（只有用户提供实际沟通结果时才记录）
- 当前可达状态
- 推荐使用方式

### 6.4 归属和可达状态标签

归属标签：
- 医生本人 — 已确认
- 医生本人 — 高度可能
- 诊所 / 个人预约渠道
- 医院 / 机构
- 科室 / 预约中心
- 助理 / 秘书
- 第三方 / 经销商
- 归属未知
- 错误关联 / 已过期 / 来源冲突

可达状态：
- 未测试
- 仅公开发布，未联系
- 消息已送达（仅实际观察到时）
- 自动回复
- 人工回复
- 医生本人确认
- 错误号码 / 无法联系
- 已拒绝 / 要求停止联系

自动回复不构成医生本人身份确认。手机号码格式、WhatsApp 图标或第三方目录按钮不构成医生本人使用 WhatsApp 的证明。

### 6.5 邮箱标签

- 个人专业邮箱
- 机构邮箱（实名）
- 科室邮箱
- 预约邮箱
- 通用邮箱
- 历史论文邮箱
- 未知归属

论文中列出的通讯邮箱可以标记为“论文验证的公开邮箱”，但不能声称当前收件有效。不得猜测邮箱地址或仅凭域名、语法格式标记为已验证。

### 6.6 联系渠道优先级

1. 已确认医生本人专业 WhatsApp / 手机
2. 已确认医生本人专业邮箱
3. 高度可能的个人专业联系渠道
4. 官方个人诊所预约渠道
5. 医院科室 / 机构官方渠道
6. 通用机构渠道
7. 第三方目录线索

不要隐藏低可信联系方式，应单独标明状态。必须给出首选联系渠道及原因；没有找到可靠记录时明确写“未找到可靠公开记录”，不能猜测或留给读者推断。

## 七、西语 WhatsApp 和邮件开发话术（附中文）

本部分必须作为报告第 3 部分，紧跟联系方式检索。

### 7.1 话术生成前检查

先阅读用户提供的完整沟通历史，按时间顺序识别：
- 实际发送的消息
- 客户实际回复
- 自动回复
- 医生本人回复
- 助理、秘书或机构回复
- 第三方转介
- 尚未发送的草稿

如果已经发过首次开发消息，不再重复完整首发版本。用户说“上次已经发了”“只补充”“追加”时，只写新增内容。

### 7.2 WhatsApp 话术

- 默认提供西语原文及完整中文翻译。
- 若客户主要使用英语，可提供英语版本，但仍按用户要求附中文。
- 保留对方 WhatsApp 显示姓名的原始顺序和拼写。
- 问候语按对方当地时间选择；不确定时使用中性问候。
- 默认简洁、自然、分段，不写成长篇产品介绍。
- 结合已核实的专业、机构和公开临床方向个性化。
- 一条消息只问一个最有价值的问题，避免连续盘问。
- 对尚未确认的临床应用使用询问句，不写成事实。
- 如果号码属于诊所、预约中心、助理或医院机构账户，话术必须向真实接收者说明联系目的，并礼貌询问是否可以转达或提供合适的专业部门渠道。
- 不得将机构自动回复描述为医生本人已回复。

### 7.3 邮件话术

- 提供西语邮件主题和正文，并附完整中文翻译。
- 收件人只能填写已知且明确预期的邮箱，不猜测地址。
- 正文包含称呼、简短身份介绍、个性化背景、一个主要沟通目的和礼貌结束语。
- 用户邮箱有自动签名时，正文末尾不要重复姓名、职位或公司名称；保留合适的结束敬语即可。
- 不得声称已附宣传册、产品目录或海报，除非用户确实提供附件并明确要求附上。
- 个人专业邮箱与机构通用邮箱必须使用不同的称呼和沟通目的。

### 7.4 默认输出内容

根据可用渠道提供：
- WhatsApp 西语原文 + 中文翻译
- 西语开发邮件（主题 + 正文）+ 中文翻译
- 如果没有个人联系渠道，提供机构/助理转接版本 + 中文翻译
- 如果已有沟通历史，提供新增消息或跟进版本，不重复已发送内容
- 不得把助手拟稿记录为已发送，也不得未经授权代替用户发送

## 八、当前执业机构及合作医院调查

本部分必须作为报告第 4 部分。

### 8.1 医生当前执业机构

逐一调查：
- 官方机构名称、别名、城市和国家
- 公立 / 私立 / 非营利 / 医疗集团属性
- 当前职位、科室、门诊或临床服务
- 医生与机构的关系：现任、兼职、合作、历史任职、论文署名或仅有目录记录
- 证据来源、发布日期及当前有效性
- 分院、集团、大学及转诊网络关系

### 8.2 合作医院与手术地点

重点查找医生实际开展手术、门诊、住院或介入操作的医院及手术中心。区分：
- 医生当前明确公布的合作医院
- 机构官方医生目录列出的工作地点
- 论文或历史资料出现的医院
- 保险目录、预约平台列出的机构
- 尚待医生或机构确认的可能合作地点

论文署名某医院不等于当前任职；医生在某机构出诊也不等于拥有设备采购权限。

### 8.3 机构联系入口

整理与后续设备开发相关的官方入口，包括医院总机、相关科室、影像科、医学工程、生物医学工程、采购和管理部门。只有来源明确时才标注具体部门或人员，不猜测部门邮箱。

## 九、学术论文、临床术式及设备需求分析

本部分必须作为报告第 5 部分。

### 9.1 学术资料检索

检索：
- PubMed、期刊原文、ORCID、Google Scholar、ResearchGate、大学研究库
- 学术会议、讲者资料、专业协会活动
- 医院/大学公布的临床项目、服务范围和手术团队介绍

每项重要资料列出标题、年份、期刊/会议、作者身份、研究内容、原始链接及其能够支持的专业判断。

### 9.2 临床方向和术式核验

明确区分：
- 医生实际公开开展的服务
- 医生本人自述的临床业务
- 论文参与的研究方向
- 医院或团队公布的服务
- 根据专业或关键词推测的潜在术式

论文参与不等于医生本人独立开展该术式；研究病例不等于当前日常业务。没有证据的术式必须标记为“待确认”。

### 9.3 影像需求判断

针对每项已证实或待确认术式，分析：
- 是否需要术前、术中或术后 X 射线影像
- 是否需要静态摄影、动态透视、造影或三维成像
- 影像由医生所在机构自有设备提供，还是由合作医院/影像中心提供
- 是否可能使用移动 DR、固定 DR、移动 C 臂、3D C 臂、固定 CathLab 或 CBCT
- 需要向医生、医院或设备部门进一步确认的问题

必须区分普通外科手术、术中透视、血管造影和固定 CathLab 的技术边界。不能因为医生属于某一外科专业就自动推定需要 C 臂。

## 十、医院设备配置、历史采购及采购负责人调查

本部分必须作为报告第 6 部分。

### 10.1 现有设备与历史配置

调查医院或合作医院公开披露的：
- X 光 / DR / CR / 移动 DR 品牌和型号
- C 臂、血管造影系统、CathLab、CBCT 等设备品牌和型号
- 设备数量、科室、安装时间、服务状态（仅在来源支持时）
- 新建手术室、影像科扩建、设备更新和维修项目
- 设备维护、球管更换、升级和耗材采购线索

严格区分当前设备、历史采购、维修合同、招标需求、意向项目和未经证实的推断。不得仅凭某设备品牌出现在采购公告中就认定设备已安装或仍在使用。

### 10.2 采购记录与预算信号

检索政府采购平台、医院招标页面、合同公告、采购计划、预算文件、供应商公告和公开项目资料。记录：
- 项目名称和采购编号
- 发布/授标/合同日期
- 采购机构和使用科室
- 设备名称、品牌、型号及数量
- 预算、成交金额和币种（仅按原始文件记录）
- 中标供应商、合同状态和交付信息
- 与目标医生或目标科室的关联程度

历史采购只能证明历史交易，不自动证明当前采购需求。金额、型号和项目状态必须引用原始文件。

### 10.3 采购决策链与联系人

分开识别：
- 临床使用者
- 科室主任 / 临床负责人
- 影像科主任 / 放射科负责人
- 医学工程 / 生物医学工程负责人
- 设备管理部门
- 采购 / 招标部门
- 财务 / 行政 / 医院管理层
- 经销商 / 进口商 / 本地售后服务商

对每位联系人记录职务、所属机构、公开联系方式、来源、联系归属和验证状态。医生可能是临床影响者，但不一定是预算持有人或采购人；无证据时标记“采购权限待确认”。

### 10.4 商业开发价值

说明该机构是否有真实设备基础、更新信号、采购项目、扩建计划、临床使用者支持或渠道合作价值。若未发现公开采购记录，应写“本轮未找到公开记录”，不能推断机构从未采购。

## 十一、Perlove 产品匹配及客户评分

本部分必须作为报告第 7 部分。

### 11.1 产品匹配原则

- Mobile DR：急诊、ICU、病房和床旁摄影。
- Fixed DR：普通摄影室、综合医院和影像中心。
- Suspended DR：适合吊架布局和摄影工作流的固定摄影室。
- Dynamic DR / DRF：已证实存在动态透视及摄影需求。
- 高频移动 C 臂：有明确术中透视和造影场景的外科应用。
- 介入型移动 C 臂：仅在临床和技术范围支持时考虑，不能默认替代固定 CathLab / 血管造影系统。
- 3D C-arm：存在明确术中三维成像需求时考虑。
- CBCT：牙科、颌面、耳鼻喉等经当地许可的应用。

### 11.2 每项匹配必须说明

- 临床场景及证据来源
- 产品类型及匹配程度
- 已确认事实与推断
- 具体适用场景
- 不适合或暂不推荐的情况
- 下一步需要确认的问题
- 是否应转向其他产品或机构采购角色

### 11.3 型号和法规边界

型号级建议前核实当前制造商资料：功率、kV、mA、mAs、脉冲频率、帧率、球管、阳极热容量、焦点、探测器尺寸和分辨率、机械运动、电源条件、DICOM/PACS、配件、安装、培训、保修、售后及目标国注册。未确认内容写“需工程师 / 法规部门确认”，不得编造认证或参数。

### 11.4 客户评分（100 分）

| 维度 | 权重 |
|---|---:|
| 临床应用匹配 | 25 |
| 采购 / 更新可能性 | 20 |
| 机构商业价值 | 15 |
| 决策影响力 / 采购链接近程度 | 15 |
| 联系方式质量 / 可达性 | 10 |
| 渠道及合作价值 | 10 |
| 信息完整度 | 5 |
| **总计** | **100** |

等级：
- A：80–100，重点开发
- B：60–79，合格开发，继续验证
- C：40–59，培育或有限投入
- D：0–39，低优先级或暂停

评分必须逐项解释并展示证据置信度（高 / 中 / 低）。缺少采购、临床或联系方式证据时不得乐观补分。未解决身份冲突的客户不得评 A。专业关键词推断不能证明具体临床需求。医生没有采购权仍可能是临床影响者，但必须准确标记。

每份评分说明：当前分数、等级、证据置信度、主要加分依据、关键扣分点、最值得补齐的信息。分数变化必须解释相较原始分数的依据。

## 十二、下一步开发计划

本部分作为报告第 8 部分。按优先级给出可执行动作，例如：
1. 优先联系哪个已验证渠道，以及原因。
2. 需要向医生确认的关键临床问题。
3. 需要进一步核实的现任机构或合作医院。
4. 应优先接触的临床、影像、医学工程或采购岗位。
5. 下一轮需要检索的具体公开资料或采购信息。

不要把已经完成的检索事项再次写成待办；不要把低价值的泛化建议堆成清单。

## 十三、客户登记摘要

本部分作为报告第 9 部分，输出一段简洁中文摘要，建议结构：

“国家 城市 专业医生。身份及专业核实状态。个人 WhatsApp / 电话 / 邮箱及验证状态。当前执业机构和合作医院。临床方向及已证实术式。潜在产品匹配及限制。机构采购线索和采购权限判断。客户等级及评分。下一步实际跟进动作。”

摘要必须保留关键联系人和业务判断，但避免重复整篇报告。用户另有 CRM 模板时，以用户当前指定模板为准。

## 十四、批量线索处理

先提供客户对比表，再为每位客户分别输出独立档案。每位医生都必须遵循上述九部分顺序。不得把一个客户的电话、邮箱、论文、机构、采购记录或评分复制给另一个同名客户。身份或专业无法区分时，单独标记冲突，不得强行合并。

## 十五、来源引用和检索覆盖

- 所有网页事实必须附来源引用及可打开的原始 URL。
- 身份、专业、联系方式、机构、论文、采购和联系人信息的来源必须紧邻对应事实。
- 优先使用官方来源和论文原文；搜索摘要仅作为线索，重要事实应尽可能打开原页面核对。
- 记录检索日期；历史页面注明年份或资料截止时间。
- 对冲突信息并列说明，不自行选择看起来更合理的一项。
- 对未访问、无法访问、付费墙或登录限制如实说明。
- 不复制大段论文或网页原文，以简洁中文总结为主。
- 可简要记录实际搜索过的来源类别及限制；不得无依据声称“遍历全网”或“全部公开信息”。
